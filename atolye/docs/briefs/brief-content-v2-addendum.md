# Addendum: this is the final version, quality over speed

The learner says: "Do this carefully; we will not come back to edit it again. Make it as strong, clear, precise and instructive as possible." Treat every file you touch as the finished textbook.

Rules on top of the brief:
1. Quality beats card/exercise count. Never pad. If a target number would force filler, write fewer, better items and say so.
2. Every explanation passes the "stranger test": a developer who knows another language but has never seen Python understands it on first read, without the code. One idea per card; order ideas so each builds on the previous; never use a concept before it is introduced (check earlier days' cards).
3. Concrete before abstract: show the example, then name the rule. Use a precise mental model (e.g. "a variable is a name tag on an object, not a box") and keep it consistent across all days.
4. Every "common mistake" shows the real error text Python prints (run it) and how to read it.
5. Turkish must read like a good Turkish textbook written by a native teacher, not a translation: natural word order, correct suffixes on code terms (`list`'e, `dict`'in), consistent terminology across days (pick one Turkish gloss per term and reuse it). English twin equally clear.
6. Exercises: every prompt states exactly what to produce (names, inputs, exact output format) so a correct solution can't fail on ambiguity; hints teach the next step of thinking, not the answer.
7. Before you report, do a full self-review pass: re-read every item you wrote as the learner, fix anything unclear, wrong, repetitive or out of order. Then run your validator to 0 failures.
8. An independent reviewer will read your days afterwards against these rules; issues it finds come back to you.
